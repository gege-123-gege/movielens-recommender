# 今天的任务：把 ItemCF 和评估指标讲清楚

用约 2 小时完成下面三步。目标是能够解释项目已经运行的部分，再进入 PyTorch 训练阶段。

## 1. 手算推荐过程（约 30 分钟）

将“不低于 4 分”记为喜欢，用 1 表示正反馈：

| 用户 | 电影 A | 电影 B | 电影 C |
| --- | ---: | ---: | ---: |
| 用户 1 | 1 | 1 | 0 |
| 用户 2 | 1 | 0 | 1 |
| 用户 3 | 0 | 1 | 1 |

A 有两名用户喜欢，C 也有两名用户喜欢，同时喜欢 A、C 的只有用户 2。

```text
sim(A, C) = 共同喜欢的人数 / sqrt(喜欢 A 的人数 × 喜欢 C 的人数)
          = 1 / sqrt(2 × 2)
          = 0.5
```

同理，sim(B, C)=0.5。对于喜欢 A、B 的用户 1：

```text
score(用户 1, C) = sim(A, C) + sim(B, C) = 1.0
```

先过滤已经评价的 A、B，再按分数推荐。余弦相似度在这个例子中是 0.5，但多个相似度累加得到的推荐分数可以超过 1。

对应源码 `recsys/models.py` 中的 `ItemCF.fit()` 和 `ItemCF.scores()`。

需要分清：`neighbors=100` 表示每部电影保存最多 100 个相似邻居；`k=10` 表示最终给用户返回最多 10 部电影。它们是两个不同参数。

## 2. 手算指标（约 30 分钟）

独立看一个评估例子：用户在评估区间喜欢的电影集合为 `{C, D}`，模型返回 `[C, X, D]`，计算 K=3 的指标。

```text
Recall@3 = 命中的喜欢电影数 / 喜欢电影总数 = 2 / 2 = 1

DCG@3  = 1/log2(2) + 0/log2(3) + 1/log2(4) = 1.5
IDCG@3 = 1/log2(2) + 1/log2(3)              ≈ 1.63093
NDCG@3 = DCG / IDCG                         ≈ 0.91972
```

如果返回 `[C, D, X]`，Recall 仍为 1，NDCG 则为 1，因为相关电影排得更靠前。

对应源码 `recsys/evaluation.py` 中的 `ranking_metrics()`。本项目是先按用户计算，再对有正反馈标签的用户做宏平均，因此不等于把全部用户的命中数和标签数分别相加后求比值。
