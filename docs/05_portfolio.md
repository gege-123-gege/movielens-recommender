# 电影推荐项目展示指南

## 三分钟命令行演示

在当前项目目录运行三条推荐命令。前两条给训练用户 6040 生成推荐，第三条展示用户 1 的冷启动结果。`positive_history_count` 是训练时评分至少为 4 分的电影数量，推荐列表排除了训练时所有已评分的电影。

```powershell
.\run.ps1 recommend --run-dir outputs/final_20261116 --model itemcf --user-id 6040 --k 5
.\run.ps1 recommend --run-dir outputs/final_20261116 --model bpr --user-id 6040 --k 5
.\run.ps1 recommend --run-dir outputs/final_20261116 --model bpr --user-id 1 --k 3
```

用户 6040 有 194 个训练正反馈。ItemCF 的第一部是《教父 2》，BPR 的第一部是 *The Manchurian Candidate* (1962)。用户 1 在训练时没有评分记录，输出会显示 `new_user: true`，前三部来自热门推荐。需要展示热门推荐对比时，把第一条命令的 `--model itemcf` 换成 `--model popularity`。

从源码包复现时，按 README 生成快照，并把上述命令的 `--run-dir` 指向实际输出目录。[复现说明](../README.md)

## 简历项目条目

**个性化电影推荐系统｜Python、NumPy、PyTorch**

- 基于 MovieLens 1M 的 100 万条评分实现热门推荐、ItemCF 和 BPR 矩阵分解，构建按时间切分、全量候选排序与已评分过滤的统一离线评估流程。
- 通过验证集对比 ItemCF 邻居数和共现阈值，按 NDCG@10 选择模型。最终测试集 ItemCF 的 NDCG@10 为 **0.2360**，较热门推荐相对提升 **8.52%**。分析了冷启动、低历史用户表现及漏推案例。[实测结果](../FINAL_RESULTS.md)

## 60 秒项目介绍

> 我做的是电影 Top-K 推荐。用 MovieLens 1M 的历史评分，把 4 分及以上当成喜欢，按时间切成训练、验证、测试三段。我实现并比较了热门推荐、ItemCF 和 BPR。ItemCF 根据共同喜欢电影的用户计算余弦相似度，BPR 用正例和未评分对照项的分差训练用户和电影向量。三个模型共用候选目录和评估协议。验证集上 ItemCF 的 NDCG@10 最高，最终测试集相对热门推荐提升 8.52%。BPR 在 Recall 和目录覆盖率上更高，我根据事先选定的 NDCG 指标用 ItemCF 做默认演示。对训练时没见过的用户，用热门电影兜底。

## 常见追问

| 可能的问题 | 回答要点 |
| --- | --- |
| ItemCF 为什么看共同喜欢的人数？ | 用其他用户的共同偏好连接电影。除以两部电影各自喜欢人数乘积的平方根后，再取相似度最高的一组邻居。 |
| 为什么没保留共同喜欢人数至少为 5 的规则？ | 门槛能移除少数用户支撑的相似关系，也会移除有用的偏好信号。在同一验证集上固定邻居数为 100 时，Recall 和 NDCG 都略降。 |
| BPR 一条样本是什么？ | `(用户, 训练正反馈电影, 未评分的训练目录电影)`。点积差是正例分数减对照分数，分差越大，`softplus(-分差)` 越小。优化器用一批样本的平均损失和正则项更新向量。 |
| 为什么 BPR 训练了 12 轮，却保存第 2 轮？ | 第 2 轮的验证 NDCG 最高，训练损失之后仍下降，但验证排序没有同步提升。 |
| 为什么 BPR 的 Recall 更高，仍选择 ItemCF？ | Recall 计命中比例，NDCG 还给靠前的命中更高权重。项目事先规定用验证 NDCG 选型。 |
| 怎么避免用到未来数据？ | 电影目录、热门度和训练样本都来自训练区间。验证集用于选超参数和轮次。最终测试用冻结模型，验证期评分记录只用于测试时排除已评分电影。 |
| 冷启动怎么处理？ | 没有可用训练偏好的用户使用热门推荐。候选电影以训练目录为限，所以新电影是当前实现的限制。 |
